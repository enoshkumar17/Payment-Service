External Client Integration Spec (WaaS)

How external frontends and client platforms (e.g. MovieHub, FoodBox) integrate with the PayPlatform Wallet-as-a-Service engine.

Client App (MovieHub) ➔ PayPlatform API (x-api-key) ➔ Double-Entry Ledger ➔ Webhook Dispatch

1

Register Platform & Obtain API Key

Every client platform registers via the Admin Dashboard and receives a unique live API key (e.g., mch_live_...). Pass this key in all HTTP requests via the x-api-key header.

2

Initiate Payment Transaction

Send a POST request to create and execute a payment. Include an idempotencyKey to prevent double-charging on network retries. 

POST /api/v1/transactions/new-transaction HTTP/1.1
Host: payment-service-pl7q.onrender.com
x-api-key: mch_live_4b8f72a1e0c395d821f06a92cb71a39d84e1a0b3f5c9e2d1
Authorization: Bearer <customer_jwt_token>
Content-Type: application/json

{
  "fromAccount": "66e1b7c12f4a5c0012a4e111",
  "toAccount": "66e1b7c12f4a5c0012a4e222",
  "amount": 250.00,
  "idempotencyKey": "order_moviehub_ticket_9921"
}
3

State Machine & Dual-Layer Verification

The backend executes a 3-step state progression: PENDING ➔ PROCESSING ➔ SUCCEEDED. The server verifies that the merchant API key is active and that the customer JWT owns the source account. An internal transaction lock guarantees zero race conditions.

4

Real-Time Webhook Verification

When a payment reaches final status, PayPlatform posts an automated webhook to your configured URL with an HMAC-SHA256 signature in x-webhook-signature: 

// Verify PayPlatform webhook in Node.js
const crypto = require("crypto");

function verifyWebhook(payload, signature, secret) {
  const hmac = crypto.createHmac("sha256", secret);
  const digest = hmac.update(JSON.stringify(payload)).digest("hex");
  return crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(digest));
}
